# Build & SDK Pin

## Hard requirement: iOS 26 SDK

Per PLAN.md, Cook Console targets the **iOS 26 SDK** (Xcode 26.x). This is a
hard project requirement, not a preference:

- `IPHONEOS_DEPLOYMENT_TARGET = 26.0` is set at project level for all targets
  in `CookConsole.xcodeproj`.
- CI runs on the `macos-26` GitHub-hosted runner image, which ships Xcode
  26.6 (default) with iOS 26.x SDKs.
- The CI job `Enforce iOS 26+ SDK` parses `xcodebuild -showsdks` and **fails
  the build if the available iOS SDK major version is older than 26**.

## Local build

```bash
# Build (Debug, simulator)
xcodebuild build -project CookConsole.xcodeproj -scheme CookConsole \
  -destination 'generic/platform=iOS Simulator' -configuration Debug

# Unit tests
xcodebuild test -project CookConsole.xcodeproj -scheme CookConsole \
  -destination 'platform=iOS Simulator,name=iPhone 17,OS=latest'
```

Build products go to `~/Library/Developer/Xcode/DerivedData/`, which
`.gitignore` excludes (`DerivedData/`, `xcuserdata/`, `*.xcuserstate`), so
`git status` stays clean after a local build.

The domain/data subset can also be compiled and tested on Linux with SwiftPM.
This is useful verification, but it does not replace the canonical iOS build:

```bash
docker run --rm --user "$(id -u):$(id -g)" \
  -e HOME=/tmp/cook-home \
  -v "$PWD:/workspace" -v "$(mktemp -d):/tmp/cook-home" \
  -w /workspace wine-vault-swift-sqlite:6.1 swift test
```

## Project regeneration

`CookConsole.xcodeproj` is generated by `Tools/gen_project.rb` (xcodeproj
gem). The generator resolves the repository from its own location, so it does
not depend on a `/work` mount or the caller's current directory. Regenerate it
instead of editing the project by hand:

```bash
ruby Tools/gen_project.rb   # requires the xcodeproj gem
```

`Package.swift` selects GRDB `7.11.1`, and `Package.resolved` locks its immutable
revision. The generator reads that lock and pins Xcode's separate package graph
to the same revision. Both SwiftPM and the generated Xcode project use Swift 6.

## Targets

| Target | Type | Notes |
|---|---|---|
| `CookConsole` | iOS app | Bundle ID `com.infinityball.cookconsole`, SwiftUI lifecycle |
| `CookConsoleTests` | unit tests | Hosted in the app; `@testable import CookConsole` |

The shared `CookConsole` scheme builds the app and runs the test target, so
`xcodebuild -scheme CookConsole test` works headlessly in CI.
